\subsection{Limitations}

The oracle condition measures perfect \emph{and selective} resolution: we modify only gold-relevant passages, simulating an upper bound where a hypothetical resolver also knows which passages are worth resolving. A deployable system would have to resolve anaphoras corpus-wide, introducing both true positives and false positives. The realistic deployable gain is therefore bounded above by oracle gain $\times$ resolution accuracy $\times$ a selectivity factor.

Our evaluation is on a single benchmark (MIRACL-id). \todo{Add note on Mr. TyDi-id replication if attempted.} Generalisation to other Indonesian retrieval contexts (legal, medical, social-media) requires additional evaluation.

The Sastrawi clitic condition (Strategy~3) depends on Sastrawi's internal Indonesian root dictionary; rare or technical-domain vocabulary may produce false positives and false negatives. \todo{Quantify if observed in failure analysis.}

The naive-strip baseline (Strategy~2) is a deliberate strawman; the more important comparison is between Keep, Sastrawi clitic, and Oracle. Naive is included to quantify the harm of a preprocessing pattern that does appear in practitioner code, not to argue that anyone should use it.
